# Development Process

## 1. Brainstorming
Discuss users, problems, features, business rules,
constraints, and technical decisions.

Record the discussion in chat-brainstorm.md.

## 2. Specification
Write detailed requirements in _docs/plan.md.
Review requirements for contradictions.

## 3. Architecture
Define components, database models,
API structure, and security requirements.

## 4. Backlog
Create GitHub Issues based on the specification.

Each issue must include:
- Problem
- Goal
- Scope
- Technical notes
- Acceptance criteria
- Testing requirements

## 5. Implementation
Choose one issue.
Create a feature branch.
Implement the requested functionality.

## 6. Quality Assurance
Run automated tests.
Check acceptance criteria.
Fix defects before completion.

## 7. Review
Review code and test results.
Merge the approved changes into main.
Close the completed GitHub Issue.

## 8. Repeat
Continue with the next issue.

## Definition of Done
An issue is complete only when implementation,
testing, and documentation are finished.
